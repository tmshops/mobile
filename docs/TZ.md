# ТЗ: мобильное приложение (Flutter) — интернет-магазин товаров из Китая

Nov 11, 2026 · @LTM

## 1. Общие сведения

Одно Flutter-приложение для Android 9+ и iOS 15+ повторяет весь клиентский функционал сайта (разделы 3–6 основного ТЗ) и работает через тот же REST API. Это ТЗ описывает только мобильную часть; бэкенд, парсер, AI-модуль и админка — вне рамок, но перечислены контракты, которые приложению от них нужны.

**Источник:** «ТЗ: интернет-магазин товаров из Китая» от 9 ноября 2026 (далее — «основное ТЗ», ссылки вида «осн. 3.6»).

**Суть продукта:** клиент выбирает товар с китайских площадок (Taobao, 1688, Tmall, позже Pinduoduo, Poizon), магазин выкупает его, консолидирует на складе в Китае и доставляет по Туркменистану через Shazada Logistics. Цены — только в TMT.

**Пользователи приложения:**

| Роль | Что доступно в приложении |
| --- | --- |
| Гость | Каталог, лента видео, поиск (в т.ч. по фото), корзина и избранное на устройстве, быстрый заказ |
| Покупатель | Всё выше + оформление и оплата, заказы, посылки, баланс, чат, отзывы, уведомления |
| Оптовик | Всё выше + оптовые цены и ассортимент, таблица «цвет × размер», счета и накладные PDF |

Сотрудники (оператор, администратор) и курьеры приложением не пользуются: админка — веб (осн. 7).

**Главные принципы:**

- Не больше 3–4 шагов от товара до оплаты; оформление заказа — один экран.
- Всё, что меняется в админке (цены, баннеры, видео, акции, тексты, статусы, тарифы, минимальная версия), приходит с сервера без релиза. В приложении нет зашитых цен, тарифов и названий статусов.
- Цена, доставка и итог всегда считает сервер; приложение только показывает и предварительно оценивает.
- Каждый экран имеет 4 состояния: загрузка, пусто, ошибка, нет интернета — на RU и TK.

## 2. Стек и архитектура

Приложение строится на Clean Architecture с делением по фичам, BLoC для состояния и Hive для локального хранения. Версии пакетов — актуальные стабильные на момент старта, фиксируются в pubspec.lock.

| Задача | Решение |
| --- | --- |
| SDK | Flutter stable (последняя на старте), Dart 3, null-safety, флейворы dev / stage / prod |
| Состояние | flutter\_bloc (Bloc для сложных экранов, Cubit для простых), equatable, freezed для состояний |
| DI | get\_it + injectable |
| Сеть | dio + retrofit, интерсепторы: токен, refresh, язык (Accept-Language: ru/tk), версия приложения, логи (только dev) |
| Модели | freezed + json\_serializable; ошибки — Either\<Failure, T> (fpdart) |
| Локальная БД | Hive (hive\_ce): гостевая корзина, избранное, просмотренные, история поиска, кэш заказов и посылок, настройки |
| Секреты | flutter\_secure\_storage: access/refresh-токены |
| Навигация | go\_router (StatefulShellRoute для нижнего меню), app\_links для глубоких ссылок |
| Локализация | gen-l10n (ARB ru/tk) + серверные тексты интерфейса (раздел 9) |
| Картинки | cached\_network\_image, превью с CDN нужного размера, photo\_view для зума |
| Видео | video\_player (HLS) или media\_kit; preload\_page\_view для ленты |
| Карты | flutter\_map (OpenStreetMap), geolocator, geocoding через API бэкенда |
| Камера и фото | image\_picker, image\_cropper (выделение области), flutter\_image\_compress |
| Push | firebase\_messaging + flutter\_local\_notifications |
| Авторизация | google\_sign\_in, sign\_in\_with\_apple (если потребует App Store), smart\_auth / sms\_autofill (Android) |
| Оплата | webview\_flutter для страницы эквайринга |
| Чат | WebSocket (web\_socket\_channel) или то, что выберет бэкенд; fallback — поллинг |
| PDF | скачивание + open\_filex / share\_plus |
| Сеть и офлайн | connectivity\_plus + реальная проверка доступности API |
| Аналитика и сбои | собственные события в API аналитики, Firebase Analytics (опц.), Crashlytics или Sentry |
| Обновление | package\_info\_plus + минимальная версия из API конфига |

**Слои Clean Architecture** (в каждой фиче):

1. **presentation** — экраны, виджеты, Bloc/Cubit. Знает только use case'ы и сущности.
2. **domain** — сущности, абстрактные репозитории, use case'ы. Чистый Dart, без Flutter и пакетов сети/БД.
3. **data** — DTO, remote (retrofit) и local (Hive) data source, реализации репозиториев, мапперы DTO → entity.

Зависимости идут только внутрь: presentation → domain ← data. Фичи не импортируют друг друга напрямую; общее (корзина-счётчик, сессия, регион) живёт в core или передаётся через глобальные Bloc'и верхнего уровня.

Domain — центр: presentation вызывает его use case'ы, data реализует его интерфейсы и только она ходит во внешние источники.

**Глобальные Bloc'и** (живут всё время работы): AuthBloc (гость / покупатель / оптовик), AppConfigCubit (конфиг с сервера), LocaleCubit, RegionCubit, CartBloc, FavoritesCubit, NotificationsCounterCubit, ConnectivityCubit.

## 3. Структура проекта

Код делится на core (общее) и features (по одной папке на бизнес-область, внутри — data / domain / presentation).

```
lib/
  main_dev.dart, main_stage.dart, main_prod.dart
  app/            # App, роутер, тема, глобальные провайдеры
  core/
    di/           # get_it + injectable
    network/      # dio, интерсепторы, обработка ошибок
    storage/      # Hive boxes, secure storage
    error/        # Failure, Exceptions
    l10n/         # ARB, серверные тексты
    theme/        # цвета, шрифты, отступы
    widgets/      # UI-кит: кнопки, плитки, цена, бейджи, состояния экрана
    utils/        # формат цены TMT, маска +993, даты
    analytics/    # события, heartbeat
    push/         # FCM, маршрутизация по push
    deeplinks/
  features/
    onboarding/   config/   auth/      home/       video_feed/
    catalog/      product/  search/    image_search/ link_import/
    cart/         checkout/ payment/   orders/     parcels/
    profile/      wallet/   favorites/ addresses/  notifications/
    support_chat/ reviews/  promotions/ wholesale/ info_pages/
    settings/
```

**Правила кода:**

- Один публичный виджет на файл; экраны — «*\_page.dart», куски — «*\_view.dart» / «\*\_widget.dart».
- Никаких строк интерфейса в коде — только ключи l10n. Никаких цветов и размеров вне theme.
- Денежные суммы — целые числа в минимальных единицах или Decimal; double для денег запрещён.
- very\_good\_analysis или flutter\_lints со строгими правилами; формат — dart format, проверка в CI.
- Кодогенерация (freezed, json, retrofit, injectable, hive adapters) через build\_runner; сгенерированные файлы коммитятся.
- API-клиент генерируется или сверяется с OpenAPI-спецификацией бэкенда (осн. 8.1).

## 4. Навигация и глубокие ссылки

Основа навигации — нижнее меню из 5 вкладок, у каждой свой стек экранов (go\_router StatefulShellRoute). Повторный тап по активной вкладке возвращает к корню и прокручивает вверх.

| Вкладка | Корневой экран | Особенности |
| --- | --- | --- |
| Главная | Лента видео + блоки главной | Шапка: логотип, поиск, кнопка «поиск по фото», RU/TK |
| Каталог | Дерево категорий | Фильтры — выезжающая панель |
| Корзина | Корзина | Бейдж с числом позиций |
| Избранное | Избранное | Отметка снижения цены |
| Профиль | Меню личного кабинета / вход для гостя | Бейдж непрочитанных уведомлений |

**Полноэкранные маршруты поверх меню:** лента видео, карточка товара, галерея, оформление заказа, оплата (WebView), вход, поиск по фото, чат, карта адреса, служебные экраны («Обновите приложение», «Техработы»).

**Guard'ы роутера:**

- Первый запуск → онбординг (язык, регион, слайды, запрос push).
- Версия ниже минимальной из конфига → экран «Обновите» без возможности закрыть. Режим техработ → экран «Техработы».
- Оформление обычного заказа, заказы, посылки, баланс, чат, отзывы → требуют входа; после входа пользователь возвращается на тот же маршрут.
- Аккаунт через Google без подтверждённого телефона → экран привязки номера перед оформлением.
- Разделы опта → только для клиентов оптовой группы (кроме заявки «Стать оптовиком»).

**Глубокие ссылки** (Android App Links + iOS Universal Links; файлы assetlinks.json и apple-app-site-association кладёт команда сайта). Ссылки сайта идут с языком в пути (RU/TK); приложение игнорирует языковой префикс и открывает нужный экран на выбранном языке. Точный формат URL согласуется с командой сайта.

| Сущность | Пример пути | Экран |
| --- | --- | --- |
| Товар | /product/{id} | Карточка товара |
| Категория | /catalog/{slug} | Список товаров |
| Акция | /promo/{id} | Страница акции |
| Заказ | /account/orders/{id} | Карточка заказа (после входа) |
| Посылка | /account/parcels/{id} | Карточка посылки |
| Оплата | /pay/{orderId} | Оплата заказа / доплаты (ссылка из SMS после быстрого заказа) |
| Возврат из эквайринга | /payment/result?… | Результат оплаты |
| Реферал | /r/{code} | Главная, код сохраняется до регистрации (этап 2) |

Кнопка «Поделиться» создаёт такую же https-ссылку (share\_plus). Push содержит поле route в том же формате — один обработчик для ссылок и уведомлений. Ссылка, открытая при холодном старте, отрабатывает после загрузки конфига и guard'ов.

## 5. Экраны и функциональные требования

Ниже — все экраны из осн. 3.9 с тем, что должно работать именно в приложении. Для каждого экрана обязательны 4 состояния (раздел 8) и поддержка pull-to-refresh там, где есть список.

### 5.1. Заставка и первый запуск

- Нативный splash (flutter\_native\_splash) → загрузка конфига (мин. версия, техработы, регионы, типы доставки, серверные тексты) с таймаутом; при ошибке — последний кэш.
- Первый запуск: выбор языка (RU / TK, по умолчанию — язык системы, иначе туркменский) → выбор региона → 2–3 слайда «как мы работаем» (можно пропустить) → пояснение и системный запрос push.
- Контент слайдов и сроки доставки — из админки.

### 5.2. Вход и регистрация

- Ввод телефона с маской +993 XX XXXXXX → ввод кода (4–6 цифр, длина из конфига). Таймер повторной отправки 60 сек, показ оставшихся попыток и блокировки из ответа API. Код живёт 5 минут.
- Android: автоподстановка кода через SMS Retriever / User Consent API (без разрешения READ\_SMS). iOS: oneTimeCode в автозаполнении.
- Код приходит в канал, выбранный клиентом (SMS / Telegram / email); первый — всегда SMS. Экран показывает, куда отправлен код (из ответа API).
- «Войти через Google»: при первом входе — запрос и SMS-подтверждение телефона. На iOS — «Войти через Apple», если потребует App Store (решить до релиза).
- Галочка согласия с политикой и обработкой персональных данных с ссылкой на текст.
- После входа: перенос гостевой корзины и избранного на сервер (merge, дубли складываются по SKU), регистрация FCM-токена, возврат на исходный маршрут.
- Заблокированный клиент видит понятное сообщение и контакты поддержки.

### 5.3. Главная

Блоки и их порядок приходят с сервера (server-driven список секций с типом и данными). Неизвестный тип секции пропускается без ошибки — так старые версии не ломаются.

- Вход в ленту видео (главный блок, см. 5.4).
- Баннер-слайдер акций (мобильная картинка, версия по языку, переход на товар / категорию / акцию / внешнюю ссылку), баннеры между блоками.
- «Скидки дня» с таймером (время окончания — с сервера, отсчёт по серверному времени с поправкой на смещение часов устройства).
- Подборки: «Хиты», «Новинки», популярные категории, рекомендации, недавно просмотренные (локально + с сервера для авторизованных) — горизонтальные карусели с «Все →».
- Блок «Как мы работаем»: заказ → выкуп → склад → доставка, сроки 3 типов доставки.
- Поле «Вставьте ссылку» (см. 5.9).
- Всплывающий баннер приложения: показ не чаще правила из админки, факт показа хранится в Hive.
- Показы и клики баннеров отправляются в аналитику (показ = баннер виден ≥ 50% площади, visibility\_detector).

### 5.4. Лента видео (Shorts / Reels)

- Вертикальный PageView на весь экран, свайп вверх/вниз. Автозапуск без звука, звук по тапу (выбор звука помнится на сессию), пауза по удержанию.
- HLS-поток с адаптивным качеством; до загрузки — превью-кадр. Предзагрузка следующего видео; одновременно живы не более 3 контроллеров (текущий, следующий, предыдущий), остальные освобождаются.
- Поверх видео — карточка товара: фото, название, цена, скидка, «В корзину» (открывает выбор SKU в bottom sheet), «Подробнее». Сбоку — лайк, избранное, поделиться.
- Порядок и пагинация (курсор) — с сервера. Лайки гостя хранятся локально и переносятся при входе.
- События для статистики: просмотр (≥ 2 сек, уточнить), досмотр (≥ 90%), переход в товар, добавление в корзину, лайк. Отправка пачками.
- Уход с экрана, сворачивание приложения, звонок → пауза. Экран не гаснет во время воспроизведения (wakelock\_plus).

### 5.5. Каталог и список товаров

- Дерево до 3 уровней с иконками: слева корневые категории, справа подкатегории сеткой (или другой паттерн из дизайна). Дерево кэшируется.
- Список: сетка в 2 колонки, бесконечная подгрузка (страница 20–40), хлебные крошки в виде заголовка с подкатегориями-чипами, баннер верха категории.
- Плитка: фото, название (2 строки), цена новая/старая, число продаж, бейджи (хит, скидка, «иллюстрация» для сгенерированного фото), сердечко избранного.
- Фильтры в выезжающей панели: цена (диапазон), источник, рейтинг продавца, продажи, цвет, размер, бренд, срок доставки, скидка. Список фильтров и значений (фасеты со счётчиками) — с сервера. Кнопка «Показать N товаров», «Сбросить», чипы активных фильтров над списком.
- Сортировка в bottom sheet: популярность, цена ↑/↓, новизна, рейтинг, продажи.
- Оптовик видит оптовые цены и товары «только опт»; розница их не видит (фильтрация на сервере).

### 5.6. Карточка товара

Сверху видно только главное: галерея, цена, варианты, доставка. Кнопки «В корзину» и «Купить сейчас» закреплены внизу.

1. **Галерея:** фото и видео в одной ленте, свайп, счётчик «3/12», тап → полноэкранный режим с зумом. Видео — превью + play. Сгенерированное фото помечено «иллюстрация», оригиналы доступны в галерее.
2. **Цена:** текущая, старая зачёркнутая, бейдж «−X%», таймер акции, ступени цены за количество. Для оптовика — таблица оптовых ступеней и мин. партия.
3. **Варианты (SKU):** цвет с миниатюрами, размер, комплектация. При выборе меняются цена, фото, остаток; недоступные комбинации неактивны. Кнопка «Размерная сетка» (с переводом китайских размеров). Выбор количества.
4. **Доставка:** 3 строки — экспресс, авиа, авто: цена по весу товара и региону + срок. Регион меняется тапом. Без веса — «доставка после взвешивания». Типы, запрещённые для товара (напр. батареи авиа), скрыты или помечены.
5. **Описание:** HTML-рендер с картинками и видео (flutter\_widget\_from\_html или аналог, ленивая загрузка картинок), свёрнуто под «Показать полностью». Разрешённые теги — whitelist, скрипты не исполняются.
6. **Характеристики:** таблица ключ–значение.
7. **Продавец:** источник, рейтинг, продажи, «Все товары продавца».
8. **Отзывы:** наши + переведённые с источника (с пометкой), фото/видео, фильтр «с фото», полный список на отдельном экране.
9. **Комментарий для оператора** к позиции («проверьте цвет») — сохраняется в позиции корзины.
10. **Действия:** «В избранное», «Поделиться», «Найти похожие» (поиск по фото товара), «Быстрый заказ», подписка на снижение цены.
11. **Блоки:** «Похожие товары», «С этим покупают».

Если сервер перепроверяет цену на источнике (данные старше N часов), карточка показывает кэш сразу и обновляет цену/наличие после ответа. Товар снят с продажи → заглушка «Нет в наличии» + похожие.

### 5.7. Поиск

- Экран поиска: история запросов (локально, до 20, с очисткой), популярные запросы с сервера.
- Автодополнение с debounce 300 мс, отмена устаревших запросов (CancelToken). Исправление опечаток и синонимы — на сервере; приложение показывает «Возможно, вы искали …».
- Результаты — тот же виджет списка, фильтров и сортировки, что в каталоге.
- Если в строку вставлена ссылка на подключённый источник — сценарий 5.9. Домены источников — из конфига. При открытии поиска ссылка в буфере обмена предлагается чипом «Открыть товар по ссылке».
- Пустой результат: подсказки + кнопки «Поиск по фото» и «Найдите мне товар».

### 5.8. Поиск по фото

1. Источник: камера или галерея (форматы JPG/PNG/WEBP/HEIC, до 10 МБ). Перед отправкой — сжатие до \~1600 px по длинной стороне, HEIC → JPEG.
2. Опционально — выделение области (кроп-рамка); отправляем фото + координаты или уже обрезанное фото (согласовать с бэкендом).
3. Результаты по степени похожести, фильтр по цене и категории. Целевое время до первых результатов — до 3 сек после загрузки; индикатор загрузки файла с прогрессом.
4. Ничего похожего → «Найдите мне товар»: заявка с этим фото и комментарием уходит оператору (для гостя — после ввода телефона).

Разрешение камеры запрашивается в момент нажатия; при отказе — пояснение и кнопка «Открыть настройки», галерея остаётся доступной.

### 5.9. Товар по ссылке

- Поле на главной и строка поиска принимают ссылку Taobao / 1688 / Tmall (позже — другие), в т.ч. короткие ссылки и текст «поделиться» из приложений маркетплейсов (ссылку из текста выделяет сервер).
- Товар уже в каталоге → сразу карточка. Нет → экран ожидания до 30–60 сек (индикатор, текст о том, что происходит, кнопка «Отмена»); приложение опрашивает статус задачи раз в 2–3 сек. При сворачивании задача продолжается на сервере; возврат на экран показывает результат.
- Успех → карточка с ценой по наценке категории и «доставка после взвешивания», если нет веса. Такой товар можно купить, но в общем каталоге он появится только после проверки оператором.
- Ошибка → «Не удалось загрузить. Передали ссылку оператору» — автоматическая заявка «Найдите мне товар».
- Приложение принимает ссылки через системное «Поделиться» (Android intent-filter ACTION\_SEND text/plain, iOS Share Extension — желательно, согласовать с заказчиком).

### 5.10. Корзина

- Позиции сгруппированы по продавцам; у группы — доставка по Китаю этого продавца. Галочки на позиции, продавце и «Выбрать все»; в заказ идут только отмеченные.
- Изменение количества (с учётом остатка и мин. партии для опта), смена SKU в bottom sheet, удаление свайпом с «Отменить», перенос в избранное.
- Оптимистичные обновления: интерфейс меняется сразу, итог пересчитывает сервер (debounce), при ошибке — откат и сообщение.
- Предупреждение на позиции, если цена или наличие изменились с момента добавления (старая → новая цена).
- Минимальная сумма заказа (общая, по типу доставки, оптовая): пока не достигнута — кнопка неактивна, «Добавьте товаров ещё на X TMT» и полоса прогресса.
- Промокод (поле + ошибка из API), списание бонусов (этап 2), автоматические скидки акций, баннер в корзине.
- Итог с разбивкой: товары, доставка по Китаю (по продавцам), международная доставка (оценка по весу, по умолчанию — авиа, и региону), скидка, бонусы, «Итого». Кнопки «Оформить» и «Быстрый заказ».
- Гостевая корзина — в Hive (товар, SKU, количество, комментарий, цена на момент добавления); итог для гостя тоже считает сервер (анонимный расчёт корзины). У авторизованного — корзина на сервере, синхронна с сайтом.

### 5.11. Быстрый заказ

- Bottom sheet: только телефон → SMS-код (аккаунт создаётся автоматически, пользователь становится авторизованным). У залогиненного — одно нажатие с подтверждением.
- Результат: экран «Заказ принят, оператор свяжется с вами» + номер. В заказах — статус «Быстрый заказ». После дозаполнения оператором заказ переходит в «Ожидает оплаты», приходит push и SMS со ссылкой /pay/{orderId}, которая открывается в приложении.

### 5.12. Оформление заказа (один экран)

Блоки идут сверху вниз, кнопка «Оплатить X TMT» закреплена внизу. Каждое изменение (регион, способ получения, тип доставки, услуги, промокод) запрашивает пересчёт у сервера (checkout preview).

1. **Получатель:** имя, фамилия, телефон (+993); из профиля. Неподтверждённый номер → SMS-подтверждение при первом заказе.
2. **Получение:** переключатель «Курьер / Самовывоз». Курьер: регион + адрес из адресной книги или новый (карта, 5.16), цена курьера по региону и порог бесплатной доставки. Самовывоз: пункт выдачи региона списком или на карте (адрес, часы, телефон), бесплатно.
3. **Тип доставки:** карточки экспресс / авиа / авто с ценой и сроком (с учётом доп. дней региона). Недоступный тип (запрещённая категория, мин. сумма) — неактивен с причиной. Один заказ = один тип доставки.
4. **Доп. услуги:** чекбоксы из справочника (фотоотчёт, проверка на брак, усиленная упаковка) с ценами; поле «Комментарий к заказу».
5. **Оплата:** карта онлайн / наличные в офисе / с баланса; переключатель «Списать с баланса X TMT» комбинируется с картой. Аванс < 100% → «К оплате сейчас X TMT, остаток Y TMT до выдачи». Превышен лимит долга → сервер требует 100%, приложение поясняет причину.
6. **Итог** с разбивкой и галочка согласия с офертой и правилом «товар под заказ, отмена только до выкупа». Без галочки кнопка неактивна.

Защита от двойного заказа: кнопка блокируется на время запроса, в запрос создания заказа передаётся Idempotency-Key. Если сервер сообщает, что цена изменилась, — показать новый итог и попросить подтвердить.

### 5.13. Оплата картой и результат

- Сервер создаёт платёж и возвращает URL страницы эквайринга → открывается в WebView внутри приложения. Возврат ловится по return-URL (перехват навигации WebView) или по глубокой ссылке.
- Финальный статус приложение всегда берёт с сервера (сервер узнаёт его из вебхука): после возврата — опрос статуса платежа до 60 сек с экраном «Проверяем оплату…». Данные карты приложение не видит и не хранит.
- «Заказ оформлен»: номер, сумма, следующий шаг, кнопки «К заказу» и «На главную». «Оплата не прошла»: причина, «Повторить оплату», заказ остаётся «Ожидает оплаты» с таймером до автоотмены.
- Тот же поток используется для доплат (вес, рост цены), остатка по авансу и пополнения баланса.

### 5.14. Профиль (меню личного кабинета)

Шапка: имя, телефон, баланс, долг (если есть, с кнопкой «Оплатить»), бонусы и уровень (этап 2), метка «Опт». Пункты: Мои заказы, Мои посылки, Доплаты и возвраты, Баланс, Адреса, Просмотренные, Мои отзывы, Подписки на снижение цены, Уведомления, Поддержка, Опт (заявка или документы), Реферальная ссылка (этап 2), Информация, Настройки. Гость видит кнопку «Войти», язык, регион, информацию.

Редактирование профиля: имя, фамилия, email (необяз.), регион. Телефон меняется через SMS-подтверждение нового номера.

### 5.15. Мои заказы и посылки

**Список заказов:** вкладки «Активные / Завершённые / Отменённые»; номер, дата, сумма, статус, превью товаров; «Повторить заказ» (добавляет доступные позиции в корзину и сообщает о недоступных).

**Карточка заказа:**

- Позиции, у каждой свой статус (раздел 6), фото со склада (галерея), трек-номер по Китаю (копирование).
- Позиция в статусе «Проблема»: описание, фото и кнопки решения из ответа API (доплатить / замена / возврат / принять), таймер, если есть.
- История статусов с датами; доставка и услуги; платежи, аванс, остаток к оплате; посылки, в которые попали позиции.
- Отмена позиции или заказа — только до статуса-границы; видимость кнопки определяет флаг canCancel из API, причина — из справочника, возврат на баланс или карту. После границы — пояснение «товар уже выкуплен под вас».
- «Оплатить» для заказа «Ожидает оплаты» с таймером автоотмены.
- Претензия на полученную позицию в течение N дней после выдачи: причина, текст, до 5 фото и видео, статус претензии.
- Счета и чеки (оптовику — счёт и накладная PDF): скачать, открыть, поделиться.
- «Написать в поддержку по заказу» — чат с привязкой.

**Мои посылки:** каждая посылка отдельно — номер, состав (какие товары из каких заказов), вес, тип доставки, шкала статусов (раздел 6), ожидаемая дата, история с датами.

- «Отправить сейчас» для посылки «Формируется», не дожидаясь остальных товаров (с подтверждением). Дни бесплатного хранения и плата за хранение, если начисляется.
- «Ожидает доплаты»: вес, расчёт (вес × тариф − уже оплачено), кнопка «Оплатить». Возврат разницы на баланс показывается строкой.
- «Готова к выдаче»: адрес пункта (открыть на карте), часы, код выдачи крупно (+ QR, если пункт сканирует), сумма к оплате. «У курьера»: имя и телефон курьера (позвонить), сумма.
- «Выдана»: предложение оставить отзыв и срок претензии.

Последние загруженные заказы и посылки доступны без интернета для просмотра (раздел 8).

### 5.16. Баланс, доплаты, адреса, избранное

- **Баланс:** сумма, долг, история операций (пополнение, списание, возврат, корректировка) с пагинацией и переходом в заказ; пополнение картой (сумма → поток 5.13).
- **Доплаты и возвраты:** список выставленных доплат (вес, рост цены) с оплатой в один клик (баланс или карта) и статусы возвратов.
- **Адреса:** список, адрес по умолчанию, добавление на карте OSM: «Моё местоположение», перетаскивание карты под меткой в центре, адрес по точке (обратное геокодирование через бэкенд), поле «квартира / ориентир». Координаты сохраняются. Регион адреса определяется по точке или выбирается.
- **Избранное и просмотренные:** сетка товаров, отметка «цена снизилась», «В корзину». Гость — локально в Hive, перенос при входе.

### 5.17. Уведомления и чат поддержки

- **Центр уведомлений:** все уведомления клиента с отметкой «прочитано», «Прочитать все», переход в заказ / посылку / акцию. Счётчик непрочитанных на иконке вкладки и бейдж иконки приложения (iOS).
- **Чат:** сообщения, фото и файлы (камера/галерея), привязка к заказу (выбор из списка), статусы отправки (отправляется / отправлено / ошибка → повторить), история с пагинацией вверх. Автоперевод — на стороне сервера. Оператор может прислать карточку товара — она рендерится как товар с переходом.
- **«Найдите мне товар»:** форма (описание + фото/ссылка), заявка попадает в чат.
- Контакты поддержки: телефон (звонок), Telegram, WhatsApp — из конфига.

### 5.18. Отзывы

Оставить отзыв можно только на полученный товар: оценка 1–5, текст, до 5 фото и 1 видео (лимит длины и размера — из конфига, загрузка с прогрессом). После отправки — «На модерации». «Мои отзывы» — список со статусами (опубликован / отклонён с причиной) и ответом магазина. Напоминание оставить отзыв — push после «Выдана».

### 5.19. Акции, опт, настройки, информация

- **Акции:** список акций и страница акции (баннер, описание, срок/таймер, товары с фильтрами).
- **Опт:** форма «Стать оптовиком» (имя, телефон, компания/ИП, город), статус заявки (на рассмотрении / одобрена / отклонена с причиной). Для оптовика в карточке товара — таблица «цвет × размер» с полями количества, итогом штук/суммы и проверкой мин. партии; всё сразу в корзину. Документы — счета и накладные PDF по заказам.
- **Настройки:** язык (переключение без перезапуска, с перезагрузкой контента), регион, канал кодов (SMS / Telegram / email — привязка канала через подтверждение), каналы и типы уведомлений (рекламные можно отключить, сервисные — нет), привязка/отвязка Google, версия приложения, выход, удаление аккаунта (требование сторов: подтверждение кодом, предупреждение о долге/активных заказах).
- **Информация:** О нас, Доставка и оплата (тарифы и сроки из API), Пункты выдачи на карте, Возврат, FAQ, Оферта, Политика, Контакты — HTML с сервера на языке пользователя.
- **Служебные:** «Не найдено», «Ошибка сервера», «Нет интернета», «Техработы», «Обновите приложение» (кнопка в Google Play / App Store).

## 6. Бизнес-правила на клиенте

Приложение не считает деньги и не решает, какой переход допустим: оно показывает то, что вернул сервер, и рисует кнопки по флагам из API. Это исключает расхождения с сайтом и правки правил без релиза.

### 6.1. Цены

- Клиент видит цены только в TMT; юани и доллары в приложении не показываются и не приходят в клиентском API.
- Формула сервера (для понимания): цена TMT = цена SKU CNY / курс CNY/USD × курс TMT/USD × (1 + наценка), округление вверх до целого маната. Пример: 65 CNY → 216 TMT при курсах 6,5 CNY и 18 TMT за 1 USD и наценке 20%.
- Доставка по Китаю — отдельной строкой на продавца, не в цене товара. Международная доставка = вес × тариф (тип × регион), не меньше мин. веса типа.
- Доставка до взвешивания — оценка. Везде, где она показана, есть пометка «уточнится после взвешивания» и инфо-подсказка.
- Формат цены: «1 216 TMT» — разделитель тысяч пробел, без дробной части (если округление в админке не изменено). Один форматтер на всё приложение.

### 6.2. Статусы

Статусы есть у позиции заказа (до склада) и у посылки (после склада). Статус заказа в целом — по самой ранней позиции (считает сервер). Набор статусов фиксирован и в коде описан enum'ом по коду; название RU/TK, цвет и флаг «уведомлять» приходят из справочника статусов. Неизвестный код → показать название из API с нейтральной иконкой.

| Код (пример) | У чего | Что показывает приложение |
| --- | --- | --- |
| quick\_order | Заказ | «Оператор свяжется с вами» |
| awaiting\_payment | Заказ | «Оплатить», таймер до автоотмены |
| paid | Позиция | «Оплачен, готовим выкуп», кнопка отмены |
| purchased | Позиция | «Выкуплен», отмена недоступна |
| to\_warehouse | Позиция | «Продавец отправил», трек по Китаю |
| in\_warehouse | Позиция | Фото товара со склада |
| problem | Позиция | Описание + кнопки решения |
| cancelled | Позиция / заказ | Причина и сумма возврата |
| forming | Посылка | Состав, «Отправить сейчас» |
| awaiting\_surcharge | Посылка | Вес, сумма доплаты, «Оплатить» |
| in\_transit | Посылка | Дата отправки и ожидаемая дата |
| customs | Посылка | «На таможне» |
| arrived\_tm | Посылка | Ожидаемая дата в регионе |
| ready\_for\_pickup | Посылка | Пункт, часы, код выдачи, сумма к оплате |
| with\_courier | Посылка | Имя и телефон курьера, сумма |
| delivered | Посылка | Предложение отзыва, срок претензии |

Коды статусов — иллюстрация; итоговые значения берутся из OpenAPI бэкенда. Шкала посылки показывает основной путь: формируется → ожидает доплаты → в пути → таможня → прибыла → готова к выдаче / у курьера → выдана; пройденные шаги — с датами, текущий — акцентом.

### 6.3. Отмена, возврат и доплаты

- Кнопка отмены видна только при canCancel = true от сервера (до статуса-границы, по умолчанию «Выкуплен»). Перед отменой — диалог с суммой и куда вернутся деньги.
- «Не подошло / передумал» после выкупа не принимается — текст правила в оформлении и в заказе.
- Решения по «Проблеме» (рост цены с таймером, нет товара, брак на складе) — список допустимых действий приходит из API; приложение просто рисует кнопки.
- Доплата по посылке = факт. вес × тариф − уже оплаченная доставка; отрицательная разница → возврат на баланс. Показываем расчёт построчно, числа — из API.
- Посылка с долгом не выдаётся: в карточке и профиле — «К оплате ещё X TMT» с кнопкой оплаты.

### 6.4. Розница и опт

Группа клиента приходит в профиле; приложение включает оптовые экраны и сетку «цвет × размер», но цены и ассортимент фильтрует сервер. После смены группы (одобрение заявки — push) приложение перезагружает профиль, корзину и сбрасывает кэш каталога. Розничные промокоды для опта по умолчанию не действуют — ошибка приходит из API.

## 7. Интеграции

Все данные идут через один REST API с сайтом; внешние SDK — только Firebase (push, Crashlytics, опц. Analytics), Google/Apple Sign-In и OSM-тайлы.

### 7.1. API

- Базовый URL и ключи — по флейвору (--dart-define / .env, не в репозитории). Версия API в пути (/api/v1).
- Заголовки каждого запроса: Authorization (если есть), Accept-Language (ru / tk), X-App-Version, X-Platform (android / ios), X-Device-Id (анонимный UUID устройства для гостевой сессии и аналитики), X-Region.
- Единый формат ошибки (code, message на языке клиента, fields) → маппинг в Failure. Сообщение для пользователя берётся из ответа; если его нет — общий текст из l10n.
- Пагинация: курсорная для ленты видео, чата и уведомлений; page/limit или курсор для каталога (по решению бэкенда).
- Таймауты: 15 сек на обычный запрос, 60 сек на загрузку файлов. Повтор только для идемпотентных GET (до 2 раз, экспоненциальная пауза); POST создания заказа и платежа — с Idempotency-Key.
- Специальные коды: 401 → refresh или выход; 403 blocked → экран блокировки; 426 / флаг в конфиге → «Обновите»; 503 maintenance → «Техработы»; 429 → «Слишком много попыток» с временем ожидания.

**Конфиг приложения** (один запрос при старте, кэш в Hive, обновление при возврате из фона раз в N минут): минимальная и рекомендуемая версии по платформам, режим техработ, регионы и пункты выдачи, типы доставки, длина SMS-кода и таймеры, мин. суммы, домены источников для распознавания ссылок, лимиты файлов, контакты и соцсети, справочник статусов, версия серверных текстов интерфейса.

### 7.2. Авторизация

- Токены: короткий access + длинный refresh в flutter\_secure\_storage. Refresh одним запросом на все параллельные 401 (очередь в интерсепторе).
- Потоки: телефон + код; Google (idToken → бэкенд); Apple (identityToken → бэкенд) при необходимости; привязка телефона к Google-аккаунту.
- Выход: отзыв refresh-токена и FCM-токена на сервере, очистка персональных Hive-боксов (заказы, посылки, профиль), язык и регион сохраняются.

### 7.3. Push-уведомления

- FCM для Android и iOS (APNs-ключ в Firebase). Токен регистрируется на сервере с языком и платформой, обновляется при onTokenRefresh и смене языка. Гость тоже регистрирует токен (для рекламных рассылок, если разрешил).
- Android: каналы уведомлений «Заказы и посылки», «Поддержка», «Акции»; разрешение POST\_NOTIFICATIONS (Android 13+) после поясняющего экрана.
- Payload: type, route (как глубокая ссылка), id сущности, опц. картинка. Переход из трёх состояний: закрыто (getInitialMessage), фон, открыто (внутренний баннер или локальное уведомление).
- Получение push о смене статуса обновляет соответствующий экран, если он открыт, и счётчик непрочитанных.
- События — по таблице осн. 7.4 (заказ оформлен/оплачен, ссылка на оплату, напоминание, выкуплен/на складе, проблема, доплата, статусы посылки, выдача, отмена/возврат, ответ поддержки, опт, реклама). Текст формирует сервер на языке клиента.

### 7.4. Оплата

Локальный интернет-эквайринг через WebView (см. 5.13). В WebView: разрешены только домены эквайрера и 3-D Secure (список из конфига), кнопка «Закрыть» с подтверждением, прогресс загрузки, обработка ошибки сети. Конкретный банк и его требования к мобильному возврату — открытый вопрос (раздел 13).

### 7.5. Карты

flutter\_map + тайлы OpenStreetMap (сервер тайлов согласовать: публичные тайлы OSM имеют ограничения на нагрузку, для продакшена нужен свой или коммерческий тайл-сервер). Атрибуция «© OpenStreetMap» обязательна. Геокодинг и обратный геокодинг — через API бэкенда (Nominatim или свой), чтобы не зависеть от лимитов и не вшивать ключи. Карта используется в: адрес доставки, выбор пункта выдачи, «Пункты выдачи», пункт в карточке посылки (с кнопкой «Маршрут» — открыть во внешнем приложении карт).

### 7.6. Аналитика и сбои

Админке нужны «онлайн сейчас» и время на экране (осн. 7.5), поэтому приложение шлёт свои события в API аналитики:

| Событие | Когда | Параметры |
| --- | --- | --- |
| screen\_open | Открытие экрана (RouteObserver) | screen, entity\_id (товар, категория), язык, платформа |
| screen\_close | Уход с экрана или сворачивание | screen, duration\_ms |
| heartbeat | Раз в 15 сек, пока приложение активно | текущий screen |
| session\_start / end | Запуск, возврат после 30 мин в фоне | — |
| commerce | Добавление в корзину, начало оформления, оплата, быстрый заказ | product\_id, sku\_id, сумма TMT |
| search | Поиск (текст / фото / ссылка) | запрос, число результатов |
| video\_\* | Лента видео | video\_id, доля просмотра, действие |
| banner\_\* | Показ и клик баннера | banner\_id, место |

События буферизуются в Hive и отправляются пачками (раз в 10–15 сек или при уходе в фон); heartbeat не буферизуется. Без интернета буфер ограничен (напр. 500 событий). Сбои — Crashlytics или Sentry (выбрать один), с версией, флейвором и user id без телефона.

## 8. Офлайн, кэш и состояния экранов

Без интернета приложение не падает и показывает последние загруженные заказы и посылки только для просмотра; все действия, меняющие данные, требуют сети.

| Данные | Хранение | Стратегия |
| --- | --- | --- |
| Конфиг, справочники, серверные тексты | Hive | Показать кэш, обновить в фоне (stale-while-revalidate) |
| Дерево категорий, главная | Hive, TTL несколько часов | Кэш сразу, обновление в фоне |
| Карточка товара | Память (LRU) | Всегда свежий запрос, цена из кэша не используется для покупки |
| Заказы, посылки (список + карточки) | Hive (персональный бокс) | Кэш + сеть; офлайн — только просмотр с плашкой «Данные на \[время\]» |
| Гостевая корзина, избранное, лайки | Hive | Источник истины до входа, затем merge на сервер |
| История поиска, просмотренные | Hive | Только локально (просмотренные — ещё и на сервере) |
| Картинки | дисковый кэш | Лимит размера, очистка старых |
| Токены | secure storage | — |

**Состояния экрана** — единый виджет из UI-кита, все тексты RU/TK:

1. **Загрузка** — скелетоны (shimmer) по форме контента, не одиночный спиннер. При подгрузке страницы — индикатор внизу списка.
2. **Пусто** — иллюстрация, текст и действие («Корзина пуста → В каталог»).
3. **Ошибка** — понятный текст + «Повторить». Ошибка действия (добавление в корзину) — SnackBar, а не замена экрана.
4. **Нет интернета** — если есть кэш: контент + верхняя плашка «Нет соединения»; если нет: полноэкранная заглушка. При появлении сети данные перезагружаются автоматически.

Неперехваченные ошибки ловятся FlutterError.onError и PlatformDispatcher.onError и уходят в сборщик сбоев; в релизе вместо красного экрана — нейтральный ErrorWidget.

## 9. Локализация и дизайн-система

### 9.1. Языки

- Языки: русский (ru) и туркменский (tk). Выбор запоминается в Hive и передаётся серверу (контент, push, SMS на языке клиента).
- Два источника текстов интерфейса: вшитые ARB (gen-l10n) и серверные тексты из админки (осн. 7.6 «Тексты интерфейса»). Серверное значение по ключу имеет приоритет, ARB — fallback. Так администратор правит тексты без релиза. Ключи одинаковы с сайтом там, где текст общий.
- Flutter не имеет полной встроенной локализации Material/Cupertino для tk: нужны свои delegate'ы (даты, кнопки диалогов, пикеры) или fallback на подходящую локаль с ручными строками. Проверить на этапе дизайна.
- Даты и числа — через intl с собственными названиями месяцев для tk, если intl их не даёт. Множественные формы — ICU plural в ARB.
- Туркменские слова длиннее русских: верстка без фиксированных ширин для текста, перенос вместо обрезания на кнопках и в нижнем меню. Каждый экран проверяется на обоих языках и при крупном системном шрифте (textScaler до 1.3).
- Шрифт поддерживает кириллицу и туркменскую латиницу (ä, ç, ň, ö, ş, ü, ý, ž); шрифт вшивается в сборку, не грузится из сети.

### 9.2. Дизайн

Ориентир по виду приложения — PAMADOR (карточки, блоки акций, оформление, отслеживание статуса), логика магазина — Золотое Яблоко; дизайн свой, без копирования. Тёмная тема не входит в ТЗ. Макеты и UI-кит — от дизайнера (Figma); в коде они становятся ThemeData + ThemeExtension.

| Токен | HEX (прибл.) | Где |
| --- | --- | --- |
| primary | #F7941D | «Купить», «В корзину», активные элементы, цены |
| primaryDark | #F26522 | Нажатие кнопок, бейджи скидок |
| accent | #FDB913 | Бейдж «Хит», звёзды рейтинга, бонусы |
| graphite | #1E1E1E | Тёмные поверхности, текст на светлом |
| background / surface | #FFFFFF / #F5F5F5 | Фон каталога и карточек |
| textPrimary / textSecondary | #222222 / #6B6B6B | Основной и вторичный текст |

Точные HEX дизайнер берёт из исходника логотипа. Остальные правила (осн. 9):

- Одно главное действие на экране; оранжевая кнопка всегда означает «купить / далее».
- Кнопки и зоны нажатия — не меньше 44×44 (лучше 48×48 dp на Android); основной текст не меньше 14–16; иконки с подписями.
- Контраст WCAG AA; белый текст на оранжевом — только жирный и крупный.
- Плоский стиль, скруглённые углы карточек и кнопок.
- Статусы заказа — с иконками и шкалой прогресса.
- Доступность: Semantics-метки у иконок-кнопок (избранное, лайк, поделиться), цена читается целиком («цена 216 манатов, было 260»).

UI-кит в коде (core/widgets): PrimaryButton, SecondaryButton, PriceText, OldPriceText, DiscountBadge, ProductTile, ProductCarousel, SkuSelector, QuantityStepper, StatusChip, StatusTimeline, SectionHeader, AppTextField, PhoneField(+993), OtpField, EmptyState, ErrorState, OfflineBanner, Skeleton-варианты. Для кита — виджетбук (widgetbook) или демо-экран в dev-флейворе.

## 10. Нефункциональные требования

| Параметр | Требование |
| --- | --- |
| Платформы | Android 9+ (API 28), iOS 15+; телефоны с шириной от 360 dp; планшеты — та же вёрстка без поломок (отдельный планшетный дизайн не требуется) |
| Ориентация | Только портретная, кроме полноэкранного видео и галереи |
| Холодный старт | До первого контента главной ≤ 3 сек на среднем Android и 4G (с кэшем — сразу) |
| Плавность | 60 fps в списках и ленте видео на среднем устройстве; проверка в profile-режиме |
| Память | Не более 3 видеоконтроллеров, картинки декодируются под размер плитки (memCacheWidth) |
| Размер | APK/AAB с split per ABI; ориентир ≤ 40 МБ скачивания; obfuscate + split-debug-info |
| Сеть | Работа на медленном и нестабильном интернете: превью картинок нужного размера с CDN, gzip, отмена неактуальных запросов |
| Стабильность | Crash-free users ≥ 99,5% |

**Безопасность:**

- Только HTTPS; cleartext запрещён (Android network\_security\_config, iOS ATS). SSL-pinning — по решению заказчика (усложняет смену сертификатов).
- Токены — только в Keychain / EncryptedSharedPreferences. Персональные Hive-боксы шифруются (ключ в secure storage).
- Никаких секретов сервера в приложении. Данные карт не проходят через код приложения.
- Логи с телефоном, кодом и токенами в релизе запрещены. Скриншоты не блокируются (клиентам нужно делиться товарами).
- Удаление аккаунта из приложения; согласие на обработку персональных данных при первом входе (законодательство Туркменистана).

**Разрешения** — всегда в момент использования, с пояснением и обработкой отказа (permission\_handler):

| Разрешение | Зачем | При отказе |
| --- | --- | --- |
| Камера | Поиск по фото, отзывы, чат, претензии | Доступна галерея |
| Фото / галерея | То же (Android 13+ — Photo Picker, без разрешения) | — |
| Геолокация (when in use) | «Моё местоположение» на карте адреса | Ручной выбор точки или ввод текстом |
| Уведомления | Статусы заказов и посылок | Плашка в настройках «Включите уведомления» |

READ\_SMS, контакты, фоновая геолокация и микрофон не запрашиваются (видео в отзыве — из галереи или системной камеры, уточнить). Info.plist содержит понятные тексты на RU и TK (InfoPlist.strings).

## 11. Тестирование, CI/CD и публикация

### 11.1. Тесты

- **Unit:** use case'ы, репозитории, мапперы DTO, форматтеры (цена, +993, даты RU/TK), парсинг ссылок и push-route. Покрытие domain + data ≥ 70%.
- **Bloc:** bloc\_test для Auth, Cart, Checkout, ProductCard, OrderDetails, VideoFeed, LinkImport.
- **Widget / golden:** ключевые виджеты UI-кита и экраны в 4 состояниях на RU и TK (ловит обрезанный туркменский текст).
- **Integration (integration\_test / patrol)** на stage-стенде — сквозные сценарии:
  1. Гость: каталог → карточка → корзина → вход по SMS → корзина перенесена.
  2. Поиск по фото → товар → оформление → оплата (тестовый режим эквайринга) → «Заказ оформлен».
  3. Быстрый заказ → ссылка на оплату открывается в приложении → оплата.
  4. Посылка «Ожидает доплаты» → оплата с баланса → статус обновился.
  5. Отмена позиции до выкупа; кнопка скрыта после выкупа.
  6. Push в закрытом приложении → открывается карточка посылки.
- **Ручной прогон** перед релизом на матрице устройств: слабый Android 9, средний Android 13–14, iPhone на iOS 15 и на последней iOS; медленная сеть и авиарежим.

### 11.2. CI/CD

- На каждый PR: dart format --set-exit-if-changed, flutter analyze, unit + widget тесты, проверка build\_runner (нет расхождений сгенерированных файлов), проверка ARB (все ключи есть в ru и tk).
- Сборка stage → Firebase App Distribution (Android) и TestFlight (iOS) для тестировщиков и заказчика.
- Релиз по тегу: AAB в Google Play (внутреннее тестирование → поэтапно), IPA в App Store Connect; загрузка символов для Crashlytics/Sentry. Инструмент — GitHub Actions / Codemagic + fastlane (на выбор исполнителя).
- Версия: semver в pubspec, build number из CI. Ключи подписи и сертификаты — в секретах CI, копии у заказчика.

### 11.3. Публикация в сторах

- Аккаунты Google Play Console и Apple Developer оформлены на заказчика; исполнитель работает как приглашённый участник.
- Карточки приложения на RU и TK (если стор не поддерживает tk как язык карточки — текст на туркменском в описании основной локали), скриншоты для телефонов и планшетов, иконки, политика конфиденциальности по URL.
- Google Play: Data safety, целевой API — текущий требуемый Google Play на момент релиза, веб-ссылка на удаление аккаунта.
- App Store: Privacy Nutrition Labels, демо-доступ для ревьюера (тестовый номер с фиксированным кодом — бэкенд должен его поддержать), возможное требование Sign in with Apple, удаление аккаунта из приложения. Физические товары оплачиваются внешним эквайрингом — In-App Purchase не нужен.
- Доступность сторов и способ распространения для пользователей в Туркменистане (регион аккаунта, прямая раздача APK) — уточнить с заказчиком до релиза (раздел 13).

## 12. Этапы и приёмка

По основному ТЗ приложение — этап 2, после MVP сайта и админки (сдвиг возможен при согласовании). К старту мобильной разработки нужны: OpenAPI-спецификация, stage-стенд с тестовыми данными, утверждённые макеты всех экранов и UI-кит.

Внутри этапа предлагается идти вехами — каждая заканчивается сборкой в App Distribution / TestFlight:

1. **Каркас:** проект, флейворы, DI, сеть, Hive, тема и UI-кит, l10n RU/TK, роутер и нижнее меню, конфиг, онбординг, «Обновите» / «Техработы», CI.
2. **Витрина:** главная, каталог, карточка товара, поиск, избранное, акции, инфо-страницы.
3. **Лента видео, поиск по фото, товар по ссылке.**
4. **Покупка:** вход (SMS, Google, Apple), корзина с синхронизацией, быстрый заказ, оформление с картой OSM, оплата и результат.
5. **После покупки:** заказы, посылки, доплаты, отмена, претензии, баланс, адреса, отзывы, офлайн-просмотр.
6. **Связь:** push и центр уведомлений, глубокие ссылки, чат поддержки, «Найдите мне товар», настройки, удаление аккаунта.
7. **Опт:** заявка, оптовые цены, сетка «цвет × размер», документы PDF.
8. **Аналитика, полировка, публикация:** события, производительность, доступность, материалы сторов, ревью Google и Apple.

Бонусы и рефералы (этап 2 осн. ТЗ) и чат-помощник (этап 3) добавляются, когда будет готов бэкенд; архитектура серверных секций главной и профиля позволяет добавить их без переделки.

**Критерии приёмки мобильной части:**

- [ ] Все экраны из осн. 3.9 реализованы и имеют 4 состояния на RU и TK.
- [ ] Ключевой сценарий осн. 8.3 (поиск по фото → оплата → выкуп → склад → доплата → выдача) проходит из приложения без ручных правок в БД.
- [ ] Изменения в админке (цены, баннеры, видео, тексты, статусы, тарифы, мин. версия) видны в приложении без новой версии.
- [ ] Push приходит на каждую смену статуса и открывает нужный экран из любого состояния приложения; ссылки сайта открываются в приложении.
- [ ] Без интернета открываются последние заказы и посылки.
- [ ] Нефункциональные требования раздела 10 выполнены на матрице устройств.
- [ ] Приложение прошло ревью и опубликовано в Google Play и App Store.
- [ ] Переданы: исходники в репозитории заказчика, README по сборке и релизу, ключи подписи, доступы Firebase. Далее — 2 недели опытной эксплуатации и гарантия не менее 3 месяцев.
